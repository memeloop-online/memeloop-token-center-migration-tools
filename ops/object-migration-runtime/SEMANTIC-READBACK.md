# Read-only semantic v2 readback

After compatible readers and migration 153 are deployed, `--phase semantic-reference-readback --checkpoint <new-pass.json> --receipt-ledger <committed-copy-directory> --reference-audit-dir <applied-pass.semantic-reference-audit> --reference-batch 32` verifies migrated current semantic references. It never requires `--writers-quiesced`, applies references, acknowledges projection, or deletes source/target objects. Use the same exact haixia training backend and source/target identity as the receipts; never reinterpret chenhouse locators.

Only final audits with `committed` or `committed_confirmed_by_reread` status are eligible. Prepared-only records, missing receipts and changed/missing current rows do not become proofs. Receipt canonical digest, source/target identity, original row identity and qualified reference must agree. Metadata is grouped by exact backend, tenant, locator, BLAKE3 and bytes before the selected object batch is read. Each object stream computes its own body integrity plus independent original framed semantic digests for all eligible request identities in that observed group. It does not buffer the body.

After external reads finish, each row is briefly locked `FOR SHARE` and its full relevant stored state is checked again. Changed rows are deferred. Proofs record object-read completion and row-recheck times and a fingerprint of the complete compared state; this is not a global database version. Proofs are atomically written and never have timestamps refreshed without a new stream. A crash between proof/progress writes can repeat that bounded object read. Audits added behind the cursor require a new pass. The reported scope is the observed committed-audit snapshot, not every database row or a global cutover.

Readback proofs are not ownership, retention release, financial release or a GC claim. No object is GC-eligible under this command. Reference-aware deletion additionally needs all current/source/pending/audit/retention/financial dependencies released and a deletion fence shared by every possible new-reference writer. The current migration-only epoch can reuse the source advisory exclusion while application training CAS writes remain disabled; enabling application writes requires their participation in that fence. Old MinIO, chenhouse unique data and receipts remain preserved.
